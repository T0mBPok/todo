# Voice ToDo

MVP голосового планировщика. Браузер записывает микрофон через MediaRecorder, локальный Whisper small в backend-контейнере превращает запись в текст, FastAPI передаёт текст локальной Qwen 3.5 через Ollama. По умолчанию задачи автоматически сохраняются в календаре после завершения записи. Можно выключить «Сразу добавлять задачи в календарь», чтобы проверить и отредактировать план перед сохранением. В PostgreSQL сохраняются черновики планов и задачи. Пока учитываются только название, начало и конец задачи.

## Запуск из уже открытого VS Code / WSL

```bash
cd ~/projects/todo
cp .env.example .env  # только при первом запуске
# Ключ API не нужен: используется установленная в WSL qwen3.5:4b
bash scripts/compose.sh up --build -d
```

Скрипт использует Docker из WSL, а если WSL integration выключена — доступный `docker.exe` из Docker Desktop. Docker Desktop должен быть запущен. FastAPI, Vue/nginx и PostgreSQL работают в контейнерах. Модель используется из уже установленной Ollama в WSL, без повторной загрузки весов. Python и Node.js на хосте не требуются. Ollama должна быть запущена: `ollama list` показывает `qwen3.5:4b`.

- Приложение: http://localhost:5173
- Swagger / API: http://localhost:8000/docs
- Проверка готовности: http://localhost:8000/api/health

В VS Code доступны задачи через Terminal → Run Task → `ToDo: запуск Docker`, `ToDo: логи`, `ToDo: тесты backend`, `ToDo: остановка`.

После изменения настроек Ollama в `.env`:

```bash
bash scripts/compose.sh up -d --force-recreate backend
```

### Голос → календарь

1. Откройте приложение в Chrome или Edge, нажмите «Говорить», разрешите микрофон.
2. Например: «Завтра в 10 встреча на час, после неё полчаса на почту».
3. Нажмите «Завершить запись». Whisper распознает аудио локально и отправит текст Qwen.
4. При включённом «Сразу добавлять задачи в календарь» события сохранятся, календарь откроет нужный день. При выключенном — появится редактируемый план.

Текст можно ввести вручную и нажать «Добавить из текста». Если дата неясна, модель задаёт вопрос — уточните запрос и повторите. Если время занято, сохранение откатывается полностью, а предложенный план остаётся на экране для исправления. Первое обращение к модели может занять больше времени из-за загрузки в видеопамять.

### Локальная модель

В `.env` заданы `OLLAMA_BASE_URL=http://host.docker.internal:11434` и `OLLAMA_MODEL=qwen3.5:4b`. Связь Docker → Ollama проверена на этом ноутбуке. При другой конфигурации хоста укажите доступный контейнеру адрес в OLLAMA_BASE_URL. Не открывайте порт Ollama в интернет.

Если Ollama остановлена, в WSL выполните `sudo systemctl start ollama`. Если модель отсутствует — `ollama pull qwen3.5:4b`. Если модель недоступна, ручное управление задачами сохраняется, а планирование возвращает понятную ошибку. Статус модели виден в `/api/health`.

## Структура backend

```text
backend/
  app/
    core/       # конфигурация, подключение БД
    tasks/      # сущность задачи / события календаря
      models.py
      schemas.py
      dao.py
      service.py
      router.py
    voice/      # router, service, schemas: временная обработка аудио без хранения
    plans/      # сущность плана: черновик и подтверждение
      models.py
      schemas.py
      dao.py
      service.py
      router.py
      ai.py     # адаптер локальной Ollama / Qwen
    main.py
  migrations/   # Alembic
  tests/        # тесты API с реальной PostgreSQL и мок ИИ
frontend/
  src/
    entities/tasks/  # API и календарь
    entities/plans/  # API и редактирование черновика
    features/voice/  # запись и распознавание речи браузером
    shared/          # общий HTTP-клиент, даты
```

Ручки принимают и возвращают схемы Pydantic, логика находится в service, работа с БД — в DAO. Миграции применяются перед стартом backend. PostgreSQL запрещает пересечения диапазонов через exclusion constraint, включая параллельные запросы. Граница интервалов `[start, end)`: соседние задачи допустимы.

План сохраняется отдельно от задач. Подтверждение создаёт все задачи одной транзакцией; при конфликте весь пакет откатывается. Повторное подтверждение того же плана возвращает ранее созданные задачи и не дублирует их. План после подтверждения нельзя подтвердить заново с другими задачами: редактируйте уже созданные задачи через календарь.

## API

- `POST /api/voice/transcribe` — тело с аудиозаписью (`audio/webm`, `audio/wav` и другие аудиоформаты), ответ `{ "text": "..." }`. Максимум 12 МиБ, браузер ограничивает запись 90 секундами.
- `GET /api/tasks?start=...&end=...` — задачи, пересекающие диапазон, либо все задачи.
- `POST /api/tasks` — создать задачу.
- `PUT /api/tasks/{id}` — изменить название и интервал.
- `DELETE /api/tasks/{id}` — удалить задачу.
- `POST /api/plans` — `{ "text": "Завтра в 10 встреча на час", "timezone": "Asia/Tomsk" }`.
- `GET /api/plans/{id}` — получить черновик / подтверждённый план.
- `POST /api/plans/{id}/confirm` — `{ "tasks": [{ "title": "Встреча", "start": "2026-10-17T10:00:00+07:00", "end": "2026-10-17T11:00:00+07:00" }] }`.

Время передаётся с часовым поясом, хранится в `TIMESTAMPTZ`, показывается в часовом поясе браузера. Введённые вручную даты тоже интерпретируются в часовом поясе браузера. При отсутствии времени ИИ ищет свободное время с 09:00 до 18:00, без длительности предполагает час; предположения видны перед сохранением.

## Проверка и обслуживание

```bash
bash scripts/compose.sh exec -T backend python -m pytest -q
bash scripts/compose.sh logs -f
bash scripts/compose.sh down
```

Тесты используют текущую PostgreSQL, каждый тест откатывает свою транзакцию. Данные сохраняются в named volume `voice-todo_postgres_data`. Не используйте `down -v`, если хотите сохранить календарь.

## Границы MVP

Встроенный календарь, без синхронизации Google/Apple/Outlook. Нет приоритетов, поездок, повторений, уведомлений и других дополнительных деталей. Голос записывается через MediaRecorder/getUserMedia, без браузерного облачного SpeechRecognition. Нужны разрешение микрофона и localhost/HTTPS. Запись отправляется в backend, распознаётся Whisper small на CPU; временный аудиофайл удаляется после обработки. Qwen получает только текст и текущие задачи. Голос и планирование не используют облачные API. При первой сборке Docker скачивает веса Whisper (~465 МБ), затем распознавание работает локально.

Приложение рассчитано на одного пользователя локально: нет аккаунтов и авторизации, порты привязаны к 127.0.0.1. Перед публичным размещением нужны авторизация, лимиты запросов и HTTPS. PostgreSQL наружу не публикуется.

Документация интеграций: [FastAPI Docker](https://fastapi.tiangolo.com/deployment/docker/), [Vue](https://vuejs.org/guide/quick-start.html), [Ollama Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs), [faster-whisper](https://github.com/SYSTRAN/faster-whisper).


## Нормализация речи и контекст

Backend передаёт модели локальную дату, точные значения «сегодня», «завтра», «послезавтра» и ближайшие дни недели. День в начале фразы применяется ко всем связанным задачам. Очевидные разговорные длительности нормализуются до вызова модели: «полтора часа» → 90 минут, «полчаса» → 30 минут. Qwen исправляет очевидные ошибки распознавания, сохраняет последние исправления пользователя и не требует адресов или названий учреждений для создания задачи.

Без дня используется сегодня, для уже прошедшего времени — завтра; без времени подбирается свободное окно 09:00–18:00. Предположения и пропущенные неясные фрагменты видны в сообщении «Понял: …» после сохранения либо в черновике. Неясный фрагмент не блокирует понятные задачи. Если нужны другие значения, укажите их явно или выключите автоматическое сохранение для проверки.


## Качество распознавания

Используется Whisper small (CPU int8) с русским языком и контекстом календарных терминов, затем отдельный вызов Qwen исправляет разговорный текст и фонетические ошибки. Только после этого второй вызов Qwen строит расписание. Исправление не может менять явно записанное числовое время: backend проверяет его сохранность. Время `13-15` приводится к `13:15`, ISO-даты не изменяются.

После обработки доступны исходная расшифровка и отдельные карточки всех добавленных задач, включая задачи на другие дни. Исходный текст можно вернуть для исправления; уже добавленные события следует редактировать в календаре, чтобы не создавать их повторно. Более крупная модель распознавания и второй вызов Qwen увеличивают время обработки. На реальном микрофоне качество зависит от громкости, шума и произношения.


## Новый голосовой ввод: GigaAM v3

Основной движок — локальная GigaAM `v3_e2e_ctc` в отдельном сервисе `speech` (CPU, 4 потока). Образ содержит веса модели; во время распознавания скачивания и облачные API не используются. При недоступности GigaAM backend использует прежний локальный Whisper Small и сообщает название движка в ответе. Порт speech не публикуется наружу.

`bash scripts/compose.sh up --build -d` запускает все четыре сервиса. При первой сборке скачиваются CPU PyTorch и веса GigaAM (~422 МиБ). Длинные записи до 90 секунд делятся на фрагменты до 22 секунд с предпочтением тихих границ — без внешнего сервиса сегментации.

В интерфейсе запись можно прослушать. Дословная расшифровка отображается отдельно от исправленного текста Qwen; оба поля не заменяют друг друга. По умолчанию автоматическое сохранение выключено: сначала виден редактируемый план. Переключатель «Сразу добавлять задачи в календарь» возвращает автоматический режим.

Диагностика: `bash scripts/compose.sh logs speech`; тесты разбиения аудио: `bash scripts/compose.sh exec -T speech python -m unittest test_audio -v`. Тесты frontend: `node --test test/voice.test.js` из frontend (либо внутри Node build-окружения).


## Календарный интерфейс

Главный экран — сетка календаря с режимами «День», «Неделя», «Месяц». Навигация: «Сегодня», стрелки, мини-календарь слева. События показываются в своих часовых интервалах. Нажмите на событие для изменения или удаления; нажмите свободный час либо «Создать» для ручного добавления. В месячном виде дата открывает день, двойной щелчок по ячейке создаёт событие.

«Голосовая запись» вверху или «Сделать запись» слева открывает отдельное окно. После завершения записи задачи автоматически сохраняются, календарь переключается на день первой задачи. Для проверки черновика отключите «Автоматически добавлять в календарь». Запись, исходная расшифровка и исправленный текст остаются доступны в этом окне. Во время записи или обработки окно закрыть нельзя; в остальное время работают крестик и Escape.


## Повторяющиеся события

Голосом: «Каждый вторник в шесть вечера ходить на тренировку». Создаётся одна еженедельная серия, первый вторник — следующий календарный вторник (если сегодня вторник, то через неделю). Также поддерживаются «по вторникам», «еженедельно», «каждый день» и «ежедневно». Дата окончания отсутствует. Повтор можно выбрать и вручную, либо изменить в черновике перед подтверждением.

Правило `recurrence` хранится в записи задачи, удалённые повторы — в `recurrence_exceptions`. Будущие события не копируются в БД: они вычисляются для открытого дня, недели или месяца. Начало повторений сохраняет местное время в часовом поясе серии при переходах летнего времени. На календаре серия отмечается ↻.

При удалении события серии доступны варианты «Только это событие» (исключение) и «Все события серии» (удаление правила и исключений). Для изменения существующей серии пока нужно удалить её и создать заново; редактор серии показывает её параметры и выбор удаления.

API:
- В `POST /api/tasks`, задачах плана и подтверждении поддерживается `recurrence: {"frequency":"weekly", "timezone":"Asia/Tomsk"}` либо `daily`, либо `null`.
- `GET /api/tasks?start=ISO&end=ISO` возвращает конкретные события диапазона до 367 дней; для серии передаются `occurrence_start` и уникальный `occurrence_id`. `id` — общий ID серии.
- `DELETE /api/tasks/{id}?scope=occurrence&occurrence_start=ISO` удаляет один повтор.
- `DELETE /api/tasks/{id}?scope=series` удаляет всю серию.
- Для удаления серии выбор scope обязателен; обычное событие удаляется как раньше.

При сохранении проверяются пересечения разовых событий и повторов. Сравнение двух бесконечных серий использует двухлетний цикл после их начала и последнего исключения, учитывая сезонные смещения часовых поясов; календарные правила продолжаются бессрочно. Все изменения календаря сериализуются транзакционной advisory-блокировкой PostgreSQL.


### Управление задачами голосом

В голосовом окне можно создавать, переносить, переименовывать и удалять события,
добавлять или заменять описание. Примеры: «Перенеси завтра тренировку на 19:00»,
«Добавь в описание тренировки: взять форму», «Удали только ближайшую тренировку»,
«Измени название встречи на Обсуждение бюджета».
При создании: «Завтра в 10 встреча. В описании: обсудить бюджет и взять ноутбук».
Если найдено несколько событий, доступны ответы «первый вариант», «второй вариант».
Область повторений: «только это событие» или «всю серию»; подтверждение —
«подтверждаю», отмена — «отмена». Если автоматическое выполнение выключено,
для нового плана можно сказать «сохрани». Все команды обрабатывает локальная Ollama.

`POST /api/commands` готовит план или команду с найденными событиями.
`POST /api/commands/{id}/execute` принимает индексы выбранных кандидатов и scope.
Команды сохраняются в PostgreSQL, повторное выполнение возвращает прежний результат.
Календарные изменения выполняются атомарно; устаревший выбор требует повторной команды.
Редактирование одного повторения создаёт отдельное событие с привязкой к серии.
Удаление серии также удаляет такие события.


### Контекстный разбор команд

Основной POST /api/commands передаёт локальной Qwen конкретные события календаря:
идентификаторы, даты, время, описания, повторения, выбранное событие, видимый диапазон
и последние сообщения. Модель возвращает структурированные операции со ссылками
на предоставленные события. Сопоставление названия после ответа модели больше
не используется в основном обработчике. Неизвестные ссылки, несовместимые
исключения и удаление события другого явно названного дня отклоняются.
Неоднозначный выбор показывается пользователю. Групповое удаление требует подтверждения.
Перед выполнением повторно проверяется состояние событий; изменения атомарны.
Размер контекста ограничен возможностями локальной модели, при превышении приложение
просит сузить запрос. Старый разбор оставлен только для сравнительных регрессионных тестов.
