# Аккаунты и синхронизация Google

Каждый аккаунт имеет отдельные задачи, календарь, сессии и OAuth-подключение. Регистрация и восстановление пароля используют существующий SMTP и восьмизначный код. После смены пароля прежние сессии завершаются.

## Автоматический обмен

В приложении откройте аватар → «Подключение Google» → «Автоматическая синхронизация». Для ранее подключённых аккаунтов переключатель нужно включить один раз. При новом подключении автосинхронизация включается после OAuth-разрешения; перед подключением приложение сообщает об обмене в обе стороны.

Синхронизируются основной календарь Google и все списки Tasks. Фоновая задача backend проверяет подключённые аккаунты примерно раз в минуту даже при закрытой вкладке. Создания, изменения, выполнения задач и удаления передаются в обе стороны. Поддерживаются события на весь день, серии и исключения повторений. Большие наборы отправляются порциями по 25 изменений.

Если запись изменена в обоих приложениях, обмен оставляет обе версии и показывает выбор в настройках Google. Пользователь выбирает версию Импульса или Google; если одна сторона удалена, кнопка прямо говорит о подтверждении удаления. REST-запросы изменений используют ETag. Tasks MCP не предоставляет условных записей: перед изменением перечитываем задачу и проверяем снимок; изменение в Google между проверкой и записью всё ещё возможно. Параллельные запуски одного аккаунта разделяются блокировкой PostgreSQL.

Интерфейс показывает время последнего обмена, оставшиеся порции, конфликты и понятные ошибки. Временные сбои повторяются автоматически; при отозванном OAuth-разрешении нужно подключить Google заново.

## Конфигурация и обновление

Основное подключение использует GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET и GOOGLE_TOKEN_KEY с разрешениями calendar.events.owned и tasks. Без MCP задачи продолжают обмениваться через REST с датой выполнения; точное время и дедлайны остаются локально.

Для обмена временем выполнения и датой дедлайна включите Tasks MCP API (`tasksmcp.googleapis.com`) и создайте отдельный OAuth-клиент Web application с флажком **Use this client for an AI-powered agent**. Redirect URI — точный PUBLIC_ORIGIN + `/api/google/callback`. Scope — `https://www.googleapis.com/auth/tasks`; в Testing добавьте пользователя в Audience → Test users. В серверный `.env` добавьте:

```dotenv
GOOGLE_TASKS_MCP_CLIENT_ID=your-new-client-id.apps.googleusercontent.com
GOOGLE_TASKS_MCP_CLIENT_SECRET=your-new-client-secret
```

Старые ключи и GOOGLE_TOKEN_KEY сохраняйте. Docker Compose передаёт новые переменные backend. После обновления через Git и пересоздания контейнеров откройте «Подключение Google» → «Подключить Tasks MCP» и выберите тот же Google-аккаунт. Грант MCP шифруется отдельно; сервер проверяет доступ к MCP перед сохранением подключения. Адрес сервиса фиксирован: `https://tasksmcp.googleapis.com/mcp/v1`.

По [официальному журналу Tasks](https://developers.google.com/workspace/tasks/release-notes), Tasks MCP объявлен общедоступным 24 ноября 2026 года, с развёртыванием до 10 дней для аккаунта. [Текущая инструкция](https://developers.google.com/workspace/tasks/guides/configure-mcp-server) предусматривает личные Google-аккаунты и Personal mode; участия в Developer Preview для общедоступного Tasks MCP она не требует. Компания, почта Workspace и покупка домена не входят в требования этого личного подключения.

Если инструмент пока возвращает `isError: true` с требованием участия проекта в Developer Preview, интерфейс показывает реальное ограничение и поясняет возможную задержку запуска. Это предположение о причине расхождения документации с фактическим доступом, а не подтверждение успешного подключения или гарантия срока. Не следует автоматически отправлять пользователя за Workspace или в Preview: повторите проверку после развёртывания, а при сохранении ошибки обратитесь в поддержку Google с номером проекта и ответом API. До успешной проверки MCP основной обмен продолжает работать через REST, существующие задачи не мигрируются и не удаляются.

В режиме OAuth External / Testing refresh token для разрешений Tasks истекает через 7 дней ([документация OAuth](https://developers.google.com/identity/protocols/oauth2#expiration)); потребуется повторный вход. Это отдельное ограничение OAuth, не объяснение отказа MCP. Для личного использования Google описывает Personal mode без отдельной проверки приложения; менять существующий Cloud-проект или OAuth-настройки ради устранения серверного ограничения запуска не требуется без дополнительной диагностики.

Миграция 0018 добавляет отдельный зашифрованный грант MCP и тип OAuth-запроса. На первом обмене REST-связи сопоставляются с MCP по ссылке Google, либо по полному уникальному совпадению доступных REST-полей. Неоднозначность останавливает обмен задачами с сообщением, без создания дублей или удаления записей. Локальные изменения при переходе требуют выбора версии. Идентификаторы задач между REST и MCP не взаимозаменяемы.

MCP обменивает день и время выполнения с IANA-часовым поясом и отдельную дату дедлайна. Google не поддерживает время дедлайна: оно сохраняется только в Импульсе, отдельно от планового времени, и сохраняется при импорте той же даты дедлайна. Google также не поддерживает дедлайны у повторяющихся задач. Календарь продолжает использовать прежний OAuth-клиент и Calendar REST API. Миграции запускаются штатной командой alembic upgrade head перед backend.

GOOGLE_SYNC_WORKER=0 отключает фоновую задачу в отдельном процессе для тестового окружения. В обычном приложении она включена по умолчанию. Тесты подменяют ответы Google и не используют реальные OAuth-гранты.

## Ошибки

Пользователь видит понятные сообщения и действия для повторной попытки. Служебные коды запросов и исключения в интерфейс не добавляются. X-Request-ID остаётся в HTTP-заголовках и серверных логах для диагностики; токены, пароли и содержимое запросов в эти логи не записываются.
